# 怎样把图解和照片转成花样

团队分工见 [PRD 第 8 节](PRD.md)。写的人不做终审，分歧没解决不发布。

## 放在哪

- 原创和已过版权期的花样放 `patterns/`，会公开。
- 别人的图解、复原稿和所有中间文件放 `lab/`，不进 repo。

运行 `node scripts/build-lab.mjs` 可以把 `lab/` 打包成一个私有页面。各读者的读法和差异报告放在 `lab/readings/`。

## 从图解转录

1. 两个全新的 Claude 各读一遍，互相不可见，也看不到别的读法。
2. Kimi 不当读图的人。试读里它读成品照片明显弱，读手绘图解时也把四段桥认成了环。它负责第 6 步查逻辑。
3. 比较：

   ```bash
   node scripts/compare-transcriptions.mjs a.json b.json
   ```

4. 不同的地方回到原图逐处判断。判断不了的标 `?` 并写进 `toConfirm`，等级留在 `sorted`，不能升级。
5. 写入花样文件，等级是 `sorted`。
6. Kimi 查逻辑：结构、对称、接耳是否合理。分歧全部解决、逻辑通过后，写入 `reviewedBy`，等级才升到 `checked`。
7. 有人照着编成功，等级才升到 `made`。

## 从成品照片复原

1. 全新的 Claude 只看成品照片读，不给任何图解。
2. 所有数字都标 `~` 和误差，推断的标 `?`。
3. 等级是 `reconstruction`，只放 `lab/`。
4. 打样，把针数改对，就变成一份真正的图解，再走上面的转录流程。

## 这些检查能证明什么

- **自动核对**只证明数字彼此一致，不能证明正确。
- **两份读法一致**说明读错的机会变小了，但两个 Claude 可能犯同样的错。
- **只有试编**才能证明图解是对的。

复原稿不承诺准确率。我们只测过两个样本，结果见 PRD 第 4 节。

## 手绘草图怎样变成图解

`js/trace-design.js` 沿草图的线条出花样，不用 AI，也不上传。每张图解都守这几条，要改先改这里：

1. 1 个梭子加 1 团线，不剪线。从顶上的环开始，沿轮廓走一圈，左右严格对称。
2. 所有桥都从同一面编，针头在外，所以桥向外鼓。图上没有向内弯的桥。轮廓凹进去的地方，是两段向外鼓的桥在一个朝里的环的底部相遇。
3. 朝里的环在反面编：编之前翻面，编完再翻回来。
4. 朝外的环（尖角上的那种）和桥同一面编，前后都不翻。
5. 翻面只出现在正反面变化的地方。图上有“翻”才翻。
6. 直线段是拉紧的桥。形状靠相邻朝里的环之间的接耳拉住，所以相邻的朝里的环必须全部接上；两端都是朝外的环时，左右之间还要至少有一处接耳。接不上就当作摆不下，不出图，并告诉画的人该怎么改。
7. 上限 240 针，优先选针数少的。标注压线或压字的版本也不出。

这些规则按梭编常识写成，还没有人照着编过。
