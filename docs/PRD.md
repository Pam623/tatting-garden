# 梭编花园产品文档

由 Claude 和 Kimi 各自独立写方案、互相审阅后合并。

## 1. 产品是什么

一个让人**看得懂、编得对**的梭编图解产品。先服务创始人自己：能编，但看复杂图解吃力。

一次典型使用：

1. 看到一个好看的花样，把图片或照片交给团队。
2. 团队在幕后转换、互审，产出统一风格的图解，每个数字都标明可信度。
3. 打开花样页，一眼看懂结构和针数。点针数表的一行，图上所有相同元素同时亮起。
4. 开始编时进入编织模式：同一张图上，当前元素实色、其余淡印，按元素前进。
5. 编完确认，花样升级为「已试编」。

## 2. 三个核心原则

1. **诚实比完整重要。** 每个数字都带来源和可信度，并直接画在图上。推测不能看起来像事实。
2. **图解由数据生成。** 不手画，图和数字才不会对不上。
3. **少而精。** 3–5 个做到位，胜过 100 个错的。

## 3. AI 放在哪

**幕后转换，网站只发布结果。** 她的 Claude、Kimi 订阅不能给网站调用，实时转换需要付费 API，而且未经审核的结果会直接交到用户手上。

## 4. 盲测数据

只给成品照片，不给图解，让模型反推，再和创始人的真实图解对比。

| 项目 | 真实 | 全新 Claude | Kimi |
|---|---|---|---|
| 小花：环 / 桥 | 5 / 0 | 5 / 0 ✓ | 5 / 5 ✗ |
| 小花：每环装饰耳 | 5 | 5 ✓ | 4–6 |
| 小花：每环针数 | 22 | 28±6（范围内，偏高） | 12–16 ✗ |
| 小花：耳间针数 | 2 | 3±1（范围内，偏高） | 无 |
| 小花：翻面 | 不翻（待确认） | 不翻 | 要翻 ✗ |
| 字母花片：环 / 桥 | 10 / 6 | 10 / 6 ✓ | 6–9 / 8–11 ✗ |
| 字母花片：大环针数 | 15 | 16±3 | 25–60 ✗ |
| 字母花片：大桥针数 | 15 | 16±4 | 8–16（范围内） |
| 字母花片：其他桥针数 | 10 | 11±3、9±3 | 8–16（范围内） |
| 字母花片：小环针数 | 12 | 13–14±3 | 15–35 ✗ |
| 字母花片：大环装饰耳 | 各 1 | 各 1 ✓ | 未分辨 |
| 字母花片：环桥顺序 | 见图解 | 基本对，三叶内部顺序错 | ✗ |
| 接耳位置 | 见图解 | 大多看不出 | 看不出 |

只有两个样本、照片也不清晰，这个结论是方向性的，不是准确率。

**结论：**

- 从照片能较可靠地得到**结构**，但**针数只是接近，不能直接照着编**，接耳位置也基本看不到。
- 反推功能值得做，产物是**一份需要打样修正的复原稿**，不是图解。
- 两家读照片的能力差距明显，分工要按这个来，不能平均分配。

## 5. 信任等级

| 等级 | 含义 | 呈现 |
|---|---|---|
| 复原稿 | 从照片推测，未试编 | 虚线、明确标注「推测」 |
| 已整理 | 从图解转录，有来源 | 正常线条，有差异处标记 |
| 已核对 | 独立复核并通过规则校验 | 正常线条 |
| 已试编 | 真人照着编成功 | 印章 |

每个数字另有来源：`source`（原图写明）、`inferred`（按对称等推断）、`estimated`（从照片估算）。

规则校验只能证明数字自洽，不能证明数字正确，所以「已核对」不等于「不会错」，页面文案也要这样说。

等级和「推测」标注必须在画廊、详情页、编织模式上一致呈现，不能只出现在详情页。

复原稿**不承诺准确率**：样本太少，第 4 节不是性能指标。验收时只检查它是否标明了每个数字的来源和误差，不检查针数是否猜对。

## 6. MVP

1. **数据格式 v2**：环、桥、接耳、装饰耳、翻面、每个数字的来源，以及规则校验。
2. **通用图解引擎**：能渲染任意环桥结构，包括字母花片。元素位置写在数据里，不做全自动排版。
3. **转化流水线**：独立转录、差异报告、规则校验。
4. **新界面**：画廊、详情页（表图联动）、编织模式。
5. **首批内容**：小花公开；字母花片和复原稿先放私有实验室。

明确不做：账号、网页上传、即时生成、Ravelry、社区、钩针棒针（等梭编验证后再说）。

## 7. 视觉方向

**植物图鉴 × 蕾丝工艺书。** 像一本印刷精良的手工书，不是便签，也不是工具后台。

- 底色：暖白亚麻 `#F7F4EC`。文字：近黑墨色 `#23262B`。
- 唯一强调色：茜草红 `#A63A2E`，只用于「当前位置」和「推测」。
- 不用绿色底，图解纸面用白色或亚麻色。
- 图解：细墨线，环用双线或粗细变化表现线的体积，接耳和装饰耳形状不同。
- 字体：标题宋体，正文系统黑体，数字用等宽旧式风格。
- 动效克制，只用淡入和高亮过渡。

她喜欢的是图解的**形式**：字母标顺序、合并针数表、`2,4,3,4○2` 这种写法。这些保留，便签的外观不保留。

## 8. 团队分工

| 工作 | 负责 | 审核 |

| 产品整合、设计、开发 | Claude | Kimi |

| 手绘或印刷图解的第二次转录 | Kimi | Claude 对比差异 |
| 设计和代码审核 | Kimi（独立模型） | 内部审查先过一遍 |
| 以用户身份挑毛病 | Kimi | |
| 最终裁决 | 真人试编 | |

铁律：写的人不做终审。分歧未决不发布。

已知局限：两个 Claude 可能犯同样的错。所以复原稿和转录稿必须走真人试编才能升到最高等级。

## 9. 风险

1. 推测稿看起来太像真的，误导用户。对策：信任等级和虚线呈现。
2. 通用图解几何可能又丑又错。对策：位置写在数据里，用真实花样验证。
3. 版权。公开站只放原创和公版内容，其他放私有实验室。
4. 只有一个用户，容易自嗨。对策：发布前隔几天冷读重编一次。
5. 产能低，依赖试编。接受这个限制。

## 10. 待创始人决定（不阻塞开发）

1. 字母花片的原作者是谁，能否公开？默认不公开。
2. 愿意试编复原稿吗？这是把推测变成图解的唯一办法。
3. 小花页面上列的四点推测是否正确？确认前继续公开，但这四点保持「推测」标注。
