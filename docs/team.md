# 团队分工

从 2026-11-13 起。

| 角色 | 谁 | 做什么 |
|---|---|---|
| 创始人 | Pam | 定方向，真手编，最终决定 |
| 用户审阅 | Fable | 以梭编用户的身份用线上网站，把发现的问题写成 issue，打 `user-review` 标签；不看代码 |
| 开发 | Opus | 接 issue，一个 issue 一个 PR，PR 正文写明关闭哪个 issue；不审自己的 PR |
| 审查 | Kimi（K3.1 Pro） | 审 Opus 的 PR：代码审查加花样模拟编织，判过或不过 |
| 调度 | 主力 Claude | 排顺序、按额度控节奏、Kimi 判过后合并上线、向 Pam 汇报 |

## 流程

1. Fable 审阅线上网站，发 issue。
2. 调度挑 issue 交给 Opus。
3. Opus 开 PR，`npm test` 全过。
4. Kimi 审查。不过就打回给 Opus 改，改完再审。
5. Kimi 判过后，调度合并上线，在线上确认，再请 Fable 确认问题已解决。

## 额度

- 工作日 9:00–18:00：5 小时额度用到 75% 就不开新任务。
- 其他时间可以用完。
- 每周额度到 80% 停止自动工作；周末最多 90%，给周一留够。
